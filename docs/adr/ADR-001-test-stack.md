## Context

Four test assemblies cover the compression core, the local filesystem
transport, the SMB transport, and a shared fixture library. The quality
attribute at stake is **analysability**: a maintainer debugging a failed
nightly run should recognise the fixture and assertion idiom immediately,
whichever assembly the failure came from.

Mixing runners also fragments CI reporting. Two adapters produce two result
formats, and coverage collection has to be configured once per framework.

## Decision

NUnit is the runner. Shouldly is the assertion library. Test doubles are
hand-written and live in the shared fixture assembly rather than being
generated by a mocking framework.

## Consequences

Hand-written doubles cost more to author than generated mocks and must be
updated whenever an interface changes. This is accepted: the interfaces here
are narrow and change rarely, and an explicit double documents expected
behaviour better than an inline setup chain.

Contributors arriving from an xUnit background will need to translate idioms.
